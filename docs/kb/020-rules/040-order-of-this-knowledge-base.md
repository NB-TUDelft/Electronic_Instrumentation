# Order of this knowledge base

This knowledge base is ordered by importance, so a reader who stops early has
still read what matters most. Its index, `docs/kb/README.md`, comes first.
The groups follow it in this order; each one is a file in `docs/kb/` with a
directory of the same name holding its sections:

1. **Course** (`010-course`).
2. **Rules** (`020-rules`): the repository map, git synchronization, scope,
   and this order.
3. **Manuals** (`030-manuals`): the BASIC format, the hardware platform, and
   the boundary with the textbook.
4. **Authoring** (`040-authoring`): naming, style, and the prose rules.
5. **Log books** (`050-logbooks`): the log book entry that ships with every
   manual.
6. **Reference** (`060-reference`): the repository layout, build and preview,
   and cross-cutting reference material.

**Layout.** Every section is one file named `<NNN>-<slug>.md`: a three-digit
prefix that orders it among its siblings, then its title in lowercase words.
A section with subsections has a directory of the same name beside it, where
they follow the same rules. Number new siblings in steps of ten so one can
later go between two without renaming either. A section file starts with
front matter, then its one `# Title`:

```markdown
---
summary: >-
  What the index says about this section, wrapped over as many indented
  lines as needed.
always_read: true
---

# Title
```

`summary` is required and always a folded block (`>-`), which needs no
quoting whatever the text says. `always_read: true` is optional; it puts the
section on the index *always read* list and marks its entry. Headings inside
a section (`##` and below) are its own structure and stay out of the index; if
a part deserves an entry, it becomes a section of its own. The housekeeping
scripts (`housekeeping.py`, `graphify.py`) live in the knowledge base root
and are not sections.

This knowledge base is committed guidance for maintainers and agents, so the
`_*.md` rule for internal working files (see Naming conventions under
Authoring) does not apply to it. Plans, drafts, and other scratch notes still
follow that rule and stay out of the knowledge base.

**The index is generated.** `docs/kb/housekeeping.py` builds the list in
`README.md` between `<!-- kb-index:start -->` and `<!-- kb-index:end -->` from
the files themselves: groups and sections in prefix order, subsections
indented under their section, each linked by path with its summary, the
*always read* ones flagged and also listed on their own at the top. The text
above the markers is written by hand and kept. Index entries join title and
summary with a colon, because prose in this repository may not use an em
dash.

- `python3 docs/kb/housekeeping.py` rewrites the list. Run it after adding,
  removing, renaming, or moving a section, or changing a title or front
  matter.
- `python3 docs/kb/housekeeping.py --check` changes nothing and fails when
  the list is stale, or when a file breaks the layout above: a bad name, a
  reused prefix, a directory without its section file, missing or unsupported
  front matter, or a file with no `# Title` or more than one. This repository
  has no test suite to run it, so run it yourself before you commit a
  knowledge base change.
- `python3 docs/kb/housekeeping.py --graph` puts the knowledge base into the
  graphify graph: its tree, and which code each section mentions. Run
  `graphify update .` first so the graph has the section files, then this
  command; see Repository map under Rules.

To keep it in that order:

- Put a new section in the group it belongs to.
- Refer to another section by its title; its path is in the index.
- Run `python3 docs/kb/housekeeping.py` and its `--check` mode in the same
  change.

Until `2026-11-21` all of this was one file, `AGENTS.md`, whose sections
were numbered 0 to 13. The split moved the section text verbatim, apart from
heading levels and relative link prefixes, and each index summary ends with
the `AGENTS.md` section number it came from, because the moved text still
refers to other sections by those numbers. `git log --follow` on a section
file stops at the split, so look up older history on the old `AGENTS.md`.
